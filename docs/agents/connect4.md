# Four in a Row minigame (internal id CONNECT4)

An in-app, untimed Four in a Row game (board 6x7, four in a row across, up and down or diagonal wins, a full board is a draw) against the character, opened from the "Play together" picker. **Mutually exclusive with a Minecraft summon** per character (gameLaunch cross-launch gate + `deps.isSummoned`). User-facing and model-facing name: **Four in a Row** (never a trademarked name; internal ids and file names keep `CONNECT4`).

## The character plays for real (261127)

- **Every column is the character's own `play(column)` tool call** (columns 1-7 from the left, as the board text shows them). The engine only enforces the rules. There is no fallback move anywhere: no "first free column", no random pick.
- **Turn runner:** `src/main/minigames/boardTurn.ts` (`runBoardTurn`), shared with Fleet Battle and modelled on chess's turn: `buildSystemBlocks` (persona, memory tail, summary, knowledge, language) with the game rules as `extraStable` and a clock pinned for the game, the chat transcript merged with the game's move log, the cache mark at the end of the thread, the volatile turn block folded on after it, and ONE fixed tool array (`play`, `remember`). Every tool_use is answered with a `tool_result` block (rejections as `is_error`).
- **Rejected moves go back to the model** as tool errors ("Column 4 is full. Open columns: ..."). A turn that ends without a legal move is retried (`runWithAttempts`, `MOVE_ATTEMPTS = 3`, backoff 1.5 s / 4 s on provider errors and timeouts, the reason folded into the next attempt's turn block). Auth/config class errors stop at once; a cloud usage limit raises the credit popup (`raiseUsageLimitPopup(err, 'connect4')`) and stops.
- **Failed state:** when every attempt fails, `aiTurnFailed = {reason, attempts}` is set and the panel shows "{name} couldn't move" with **Try again** (`CONNECT4:retry` -> `retryAiTurn`), which runs the character's turn again. Reasons: `timeout`, `illegal_move`, `no_move`, `provider_error`, `auth`, `credit_wall`, `rate_limited` (`src/shared/minigameTurn.ts`).
- **Budgets:** each provider call uses chat's `CHAT_TIMEOUT_MS` (30 s, raised by `providerTimeoutMs` for slow providers); one attempt gets `attemptBudgetMs(llm)` = max(90 s, twice the provider's per-call floor), so Ollama's 120 s cold-load floor gets 240 s.
- **Turn tokens:** turns run on one fsm.js priority queue per session (single-flight; P1 player chat, P2 the character's move, no idle ticks). Each move turn takes a fresh `moveToken`; the tool handler applies a move only while the game is active, it is the character's colour to move, and the token is current. A game end bumps `turnSeq` and aborts the in-flight call.
- **The turn owns the board until the runner returns.** The tool handler puts the piece on the board (and pushes it), but the turn passes to the player, or the game ends, only in `dispatchMove` after the runner came back, once the move's line has landed. Flipping the turn inside the tool call made the runner's own stale check fire: the line was dropped and the move was not counted (caught by `connect4Service.test.ts`). `appliedToken` records the token whose move is on the board, so an attempt that throws after its move landed (a chat-store write failing while the line lands) reports the move instead of retrying into a second move.
- **Table talk = the `say` field of `play()` (`SAY_PROPERTY` in boardTurn.ts).** On a move turn plain text is the model's private working-out and is never shown (logged as `scratch (private)`); only the `say` of the call that landed is spoken, buffered until the move lands. A rejected call's `say` is dropped. Same split as the bot's say() (260616). Measured 261127 with Haiku 5.5: with plain text as speech, every move's board analysis ("Board check: red has col 4 rows 1 and 3...") reached the player. The turn block adds one quiet nudge when the character spoke with its previous move. Chat replies (`handlePlayerChat`, routed in `chat:send` after chess and Draw!) and the one game-over reaction (not on abandon, not on the credit wall) speak their plain text, as chess does, and stop after the first hop that said something. Speech goes through the chess path (`splitReply`, silence filter, `voice: true` on a call, persisted + pushed). **Chat-reply turns (261128 eval):** the player lines the reply is for are moved to the end of the thread (`buildGameThread(..., unansweredIds)`) and quoted in the turn block (`unansweredNote`); in time order a line typed during her move sat before the move and her move line, and Haiku answered "Ren hasn't said anything yet" 4/4. The block also states whose turn it is, and the contract extends "never say which column" to chat. `LONGER_HELP_REPLIES` (boardTurn.ts, ON since product call 261128) lets a how-to-play / help question get two or three short lines.
- **Teaching a beginner (T567).** The contract carries a teaching paragraph (`TEACHING_LEAD` in boardTurn.ts plus the game's rules and true tips): when the player is new or asks to be taught, the character states the rules plainly and correctly whatever the persona ("you know this game well", no "i'm still learning too"), then gives one tip at a time when it fits, and the `say` of its move may be a tip about the player's last move. Chat-reply turns name both sides in the board header ("Ren is red (R), Sui (you) is yellow (Y)") and add checked facts written the way she says them to the player (`connect4ChatFacts`: the player's lines "for you to build on" and hers "for you to block", each with room to make four or blocked, `linesText`; the spaces that would complete four and whether they can be played now, `fourChancesText`), plus "a tip never says to block your own colour". Chat only, so the move turn still reads the board itself. Measured with `scripts/minigame-eval/probe-teach.eval.ts` (eval branch) on 4 characters: asked "what should i watch for?", every character answered from its own seat ("column 5 stops red's diagonal" to the red player) until the facts were labelled by what they mean to the player. Every chat-reply block ends with `SPOKEN_NOW`: Lyra planned her answer in plain text on chat turns and it was all spoken. The `say` of its own move never claims what its piece blocks or sets up: in full games 3 of 4 characters announced blocks that were not blocks ("i'm blocking the right side" while the winning square stayed open). The tips also say a line only needs room for four along its own direction (Sui told a beginner "you need both sides to make four").

- **Say before the move, reaction after it (T568).** The `say` of a legal `play()` is said BEFORE the piece lands (`ToolOutcome.apply` in boardTurn.ts runs after the say is persisted), so it is about the player's last move or the game so far; written in the same call as the move, it never saw the board after it. When the piece leaves someone a chance to make four right now (`winningColumns` for either side, `reactionText`), the tool_result carries that as checked facts in the player's frame ("You, Ren, can win right now: ... your win to take, not a line to block" / "I can win next move: ... you have to block it now") and the model gets ONE more hop (max 200 tokens) whose plain text is said out loud. No reaction on a quiet move or on a move that ends the game (the game-over turn speaks). Cost: one extra call only on threat moves; C4 skill games vs the heuristic baseline (4 chars x 4 games, same seeds), base vs three runs over the T568 commits: outcomes identical seed by seed (8W/8L every run), missed wins 0 in all, each lost game has one decisive slip in every run (missed blocks plus gave-wins 7 base vs 7, 6, 8), calls 106 to 126-138, cost per game +11 to 17%. The reaction facts are not carried into the next move turn (the thread is the chat and the move log), so they never pick her move. Only a taught game is nudged toward warning the player; otherwise she plays to win. The harness logged her move only at the learner's turn, after her line, which made the judge read correct post-move lines as early (`teach.eval.ts` now logs moves from `pushState`).
- **Chat replies show no grid (T568):** the board is column by column as "yours" / "mine" (`columnsSpoken`), her lines come first as "What you have to watch out for", the player's as "yours to build on and never to block", and `FACTS_WIN` says the facts outrank what the player says (never quoted as facts). With the R/Y grid, 3 of 4 characters told the red player to block red's own diagonal. The contract also says their pieces are "yours" to their face, never "red" or "they". Chat facts lead with the chances to make four, each with what it means to the player ("your win to take, not a line to block" / "so you have to block it there now"), and a four that is not playable yet says that the piece filling the space under it hands it over (Marv told the player to "block column 5 now", the move that gave him the win). The game-over turn names who won in the speaking frame like Fleet Battle's ("Said to Ren, that is \"I won\" and \"you lost\""): with "You won with your red pieces" Marv and Lyra told the losing player "you won". The move turn gives the player's last piece the way she says it ("your last piece went into column 6, on the bottom row"), and the say is never about the move it rides on.

## Rules and state

- Red always opens. The player picks Red / Yellow / Random on the launch screen; Rematch keeps the player's colour (the launch screen lets them change it).
- `isWinningPiece` checks the four directions through the last piece; 42 pieces with no line is a draw. Resign = the character wins.
- **Service:** `src/main/connect4/connect4Service.ts` (one session per character). Contract: `src/shared/connect4Ipc.ts`. State is in memory only: like chess, a game does not survive an app restart.
- **IPC:** `CONNECT4:start` / `get-state` / `move` / `resign` / `rematch` / `retry` / `end`, push `CONNECT4:state`. RendererApi: `CONNECT4Start` / `GetState` / `Move` / `Resign` / `Rematch` / `Retry` / `End` / `onCONNECT4State`.
- **Teardown:** `endAllCONNECT4(reason)` from `endAccountSessions` (account switch), `endGameSurfacesForQuit` (app quit, before the analytics flush), factory reset; `shutdownCONNECT4` at quit. The WorldLink game-surface probe counts a live game.
- Not a bot game: it is NOT in `GAME_IDS` / `GameId` (those mirror the bot's `GAME_KINDS`). The picker opens it through `LaunchGameId` in `lib/gameLaunch.ts`.
- **UI (3D, 261127):** `Connect4Panel.tsx` (launch side picker, resign, Try again, result HUD, `tabletop/TabletopHud.module.css`) over `Connect4Board3D.tsx` (input, optimistic disc, turn line) over `three/Connect4Scene.ts`: an upright painted-wood frame on the shared `tabletop/TabletopStage.ts` (the chess table and lights), disc stacks per side, discs drop with gravity and bounce, a column highlight + ghost disc on hover, the winning four ring and pulse (`connect4Util.winningCells`; the result carries no line). The turn line says "Your turn" / "<name>'s turn" / "<name> is thinking…", and "<name> couldn't move" with a borderless Try again when `aiTurnFailed` is set. At game end the camera pulls back and slides up by the result card's pixel strip (`endFraming`). Keys: Left/Right/Home/End, Enter or Space. On demand rendering plus a 24 fps ambient tier (thinking ghost, win pulse) that reuses the last shadow map, pauses when the window is unfocused, sleeps 30 s after the last input and is off on software WebGL; GPU resources are disposed on unmount. Copy for the 3D surfaces lives in `lib/i18n/tabletop3d.ts`.

## Analytics (shape only, never board contents or chat)

- `connect4_game_started {character_id, player_color, ai_color, player_choice, rematch}`
- `connect4_first_move {character_id, by, ms_since_start}`
- `connect4_turn_failed {character_id, reason, attempts, error_class, move_number}`; each failed attempt also sends `surface_error {surface:'connect4', error_class:'move_turn_<class>'}`
- `connect4_turn_retry {character_id, reason, move_number}` (Try again pressed)
- `connect4_game_ended {character_id, duration_ms, plies, player_moves, llm_moves, engine_moves (always 0), retries, illegal_moves, failed_turns, retry_clicks, chat_replies, spoke, reason, outcome}`; `reason` is `account_switch` / `app_quit` / `factory_reset` when those ended it.
- Renderer funnel: the picker launch, then the events above. Continuity OUT: one `{kind:'play', game:'Four in a Row'}` row (`playSummaryText`), then `foldIfDue(id, persona.expanded)`.
