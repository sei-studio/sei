# Battleship minigame (Battleship)

An in-app, untimed Battleship game (two 10x10 grids, 5 ships each: carrier 5, battleship 4, cruiser 3, submarine 3, destroyer 2) against the character, launched from the "Play together" tiles. **Mutually exclusive with a Minecraft summon** per character (enforced by gameLaunch + isSummoned gate).

- **Placement phase (261124).** `startBATTLESHIP` opens the game in status `preparing` with the player's grid EMPTY: the player places their own five ships (pick a ship, `Rotate`, tap a cell; tap a placed ship to take it back; `Random` rolls a fleet) and confirms through `BATTLESHIPPlaceFleet(characterId, ships | null)`, which validates the fleet (all five names, in bounds, no overlaps) and only then flips the status to `active`, sets `startedAt` and gives the first turn to `pendingPlayerStarts`. `null` asks main to place a random fleet. The AI fleet is random and hidden as before. Pure helpers (`placementCells`, `placementFits`, `fleetCells`, `randomFleetPlacement`) live in `src/shared/battleshipIpc.ts` so the panel's draft and main's validation agree.

- **No engine, no model download.** The character picks its shot via the LLM calling a `fire(row, col)` tool (row/col 0-9). If the model does not produce a legal cell, a random free cell is fired so the game never stalls (`BATTLESHIP_MAX_HOPS=5`, `TURN_TIMEOUT_MS=90000`).
- **The AI's shot record is `playerGrid`, never `aiVisibleGrid` (261125).** `aiVisibleGrid` is the *player's* view of the AI fleet: it only changes when the player fires. Reading it as "the AI's own board" made the board text show the player's shots, made every cell look legal to the model (so it re-fired cells it had already bombed) and pinned the fallback to (0,0). Result: the turn returned to the player with the board unchanged, which read as "the companion is not playing". `aiCanFireAt` / `aiLegalCells` (playerGrid `empty` or `ship` = unfired) are the only legal-cell source for the AI turn, its prompt board and the fallback; `battleshipService.test.ts` pins that each AI turn marks one NEW cell.
- **A failing AI turn never blocks the board (261124).** Same fix as Forza 4: the setup awaits and the old `finally` re-enqueue meant a persistent model error or the 90s timeout left the turn on the AI forever (no shot, player grid dead). `runAiTurn` now wraps the whole turn and every failure path plays `aiFallbackShot` (first free cell) and returns the turn to the player. Nothing re-enqueues from `finally`.
- **Service:** `src/main/battleship/battleshipService.ts` owns authoritative state (one session per character, `sessions` Map), shot validation, ship placement, all-ships-sunk detection, and the `fire`/`remember` tool runner. Protocol contract: `src/shared/battleshipIpc.ts`.
- **Analytics / instrumentation:** `BATTLESHIP_game_started` (character_id, player_starts) and `BATTLESHIP_game_ended` (duration_ms, shots, reason, outcome). Continuity OUT: one `event: {kind:'play'}` transcript row at end, then `foldIfDue`.
- **Account switch:** `endAllBATTLESHIP` ends all live sessions (reason `abandoned`) before the scope moves, wired into `accountSessions.ts` after CONNECT4.
- **UI (3D, 261127):** `BattleshipPanel.tsx` (launch / resign / result HUD, `tabletop/TabletopHud.module.css`) over `FleetBoard3D.tsx` (input, fleet-setup draft, turn line, shot callouts) over `three/FleetScene.ts` (two walnut sea trays on the shared `tabletop/TabletopStage.ts`, the chess table and lights). Water is one patched MeshStandardMaterial per tray (bands + shader grid lines); ships are merged vertex-colored toy geometries (`three/shipGeometry.ts`, original designs). Pegs: white miss with splash, red hit with flame and smoke, the same on both grids; a sunk ship lists and settles over a slick and stays visible. Setup: harbor board on the right, drag/click/keys 1-5, arrows, R, Enter, Esc. The enemy grid carries no ships, so sunk enemy ships are rebuilt from 'sunk' cells + history (`fleetUtil.enemySunkShips`), and who fired each history entry is inferred from turn alternation (`shotOwners`). Rendering is on demand plus a 24 fps ambient tier that sleeps 30 s after the last input; GPU resources are disposed on unmount. New copy lives in `lib/i18n/tabletop3d.ts`.
- **Record:** per-character match metadata (winner, reason, shot count, duration) rides on `BATTLESHIP_game_ended`; `result.winner === 'player'` means player win, `null` draw.
- **IPC:** `BATTLESHIP:start` / `get-state` / `place-fleet` / `move` / `resign` / `rematch` / `end`, plus push `BATTLESHIP:state` on every change. RendererApi: `BATTLESHIPStart`/`GetState`/`PlaceFleet`/`Move`/`Resign`/`Rematch`/`End`/`onBATTLESHIPState`.
- **Shared registrations:** `GameId` += `BATTLESHIP`; `GAME_CATALOG` entry `{id:'BATTLESHIP', name:'Battleship', available:true}`; `GAME_PACKS` entry (no pack, `requiredPaths: []`); `BOT_ERROR_ROUTES.BATTLESHIP = {}`; `GAME_SURFACES.BATTLESHIP = withGame('BATTLESHIP')`; `summonFlows.BATTLESHIP` default flow; `PLAN_GAMES.BATTLESHIP = 'Battleship'` (bot/brain/nextStep.js); `WorldState` member `({ game: 'BATTLESHIP' } & GenericWorldState)`.
- **i18n:** keys in es/it/ja/pt-BR/ru/zh (placeholder English values where not translated). No em dashes in user copy.
