# Co-op mode (260805)

Co-op is a sibling mode of the backseat share, not a new surface. Same call,
same capture, same four wakes, same thread. What changes: the contract becomes
a tutor's, the companion gets game knowledge (a cached brief plus web search),
it keeps per-game player notes across sessions, and it can point at the screen.

Name: Co-op. Icon: circle with a four-point star inside.

Target jobs, in test order: Stardew from zero (tests the contract, model
knowledge alone suffices), Destiny 2 returning player (tests the knowledge
stack, training data is actively wrong post June 2026), No Man's Sky ongoing
(tests notes and lookup).

## M0. Mode fork and contract (client only, no infra)

- `mode: 'backseat' | 'coop'` chosen in `ShareScreenModal`, carried through
  the StartShare IPC into session state. Update BOTH zod schemas
  (`shared/backseatIpc.ts`, `main/ipc.ts`); the gridSmall incident (260804) was
  a schema silently eating a new field.
- `COOP_CONTRACT` in `backseatPrompts.ts`. Keeps the shared blocks (grid
  reading, previous image, they-can-talk-back, always-speak, repetition).
  Replaces THE POINT OF A LINE with the tutor version: the player sees the
  screen, so spend the line on what they do not have, which here is knowledge
  and direction, not narration. BAD/GOOD pairs name the walkthrough sentence
  ("Press E to open your inventory, then select...") per the 260803 finding:
  name the sentence, not the rule. Plus: teach the system never the outcome
  (spoiler rule), say so when unsure (search results and briefs go stale, a
  wrong keybind is worse than no line), dashes still stripped in code.
- Density taper: co-op idle timer starts denser ([8 s, 30 s] for the first
  ~15 min of a session) and relaxes to backseat's [12 s, 60 s]. Session-clock
  multiplier on the existing shifted exponential, no new mechanism.
- Full-res look on user ticks: captureWorker keeps the latest native frame;
  a `user` tick attaches one 1568-long-edge JPEG after the grid (~1.6k tokens,
  user ticks only). 602x336 cells cannot read menu text, and "what does this
  icon do" is the core co-op question.
- Brief injection point with a local override: a hand-written
  `coopBrief/<key>.md` in the profile dir is injected as its own cached system
  block. Lets M0 ship a hand-written Stardew brief and validate the whole idea
  before any proxy work.
- Verify: `backseat-sim --coop` on existing clips plus a live Stardew session
  (session logs, never launching electron from here).

M0 is the falsifiable test. If a live Stardew session is not fun and useful,
stop and rework the contract before building M1-M4.

## M1. Brief pipeline (proxy + Supabase)

- Table `game_briefs`: `game_key`, `title`, `brief_md`, `sources jsonb`,
  `status ('pending'|'ready'|'failed')`, `generated_at`, `model`. Plus
  `game_titles` mapping raw window titles to canonical keys (titles are dirty:
  "Stardew Valley 1.6.15 - GOG").
- Proxy `GET /coop/brief?title=...`: normalize title (small-model call, cached
  in `game_titles`), return ready brief, or insert pending, kick a background
  generation job, return 202. Client retries with backoff; the session runs
  briefless until it lands (model knowledge is the floor; injection is one
  cache miss). Never a blocking "please wait" screen.
- Generation job: Sonnet 5 (matches the knowledge-compaction precedent) with
  the Anthropic `web_search` server tool. Brief template, 3-5k tokens:
  1. what this is + what changed since ~2025 that the model will confidently
     get wrong (the whole point for D2-class games)
  2. the first-hours arc and that slow is normal
  3. vocabulary
  4. common new-player mistakes
  5. spoiler map (what not to reveal, when)
  6. default keybinds
  7. authoritative domains for this game (consumed by M2 `allowed_domains`)
- Gate: `coopBriefDailyGate` following the `skinDailyGate` pattern. TTL 90 d
  default, regenerate lazily on expiry; rows reviewable/editable in Supabase
  (a bad brief poisons every future user of that game).
- Seed script for the top ~30 games so the first-user wait basically never
  happens live.
- Deploy order per the 260725 incident: migration ships with the proxy code,
  dev app first, prod after.

## M2. Web search (no new search infrastructure)

Finding: the Anthropic API server-side `web_search` tool replaces the planned
proxy search endpoint entirely. Declared in `tools`, executed on Anthropic's
side, results return in the same request. BYOK gets it natively; the cloud
path forwards `/v1/messages` so it passes through the proxy unchanged.

- Attach on `user` ticks only, `max_uses: 3`, `allowed_domains` from the
  brief's source list (generic search returns content-farm sludge). Never on
  jolt/idle ticks: tool attachment suppresses speech (measured 100% -> 68%),
  and a user tick always answers so there is nothing to suppress.
- Haiku 4.5 uses the basic `web_search_20250305` variant (the `_20260209`
  dynamic-filtering variant is Opus/Sonnet 4.6+).
- Dead air: switch the user-tick turn to STREAMING (chatService already
  streams voice replies sentence-by-sentence). The model's pre-search sentence
  ("hold on, let me look") is spoken while the search executes server-side.
- Loop mechanics: handle `stop_reason: 'pause_turn'` by re-sending, and
  server-tool errors which arrive as an error object inside the result block
  with HTTP 200, not an exception.
- Proxy billing: extend `pricing.ts`/`usage.ts` to meter
  `server_tool_use` search counts (~$10 per 1k searches, verify current price
  at implementation) into the credit ledger, plus a per-user daily search cap.
  Do not ship another unmetered endpoint (open 260728 finding).
- Cache note: user ticks carry a different tool array than idle ticks, which
  forks the prompt cache into two lineages (tools render at position 0). This
  is deliberate; the alternative (always attach) pays speech suppression on
  every tick. Existing cacheRead logging will show the real cost.

## M3. Game notes (ongoing player knowledge)

Not a vector or graph store. Per game the content is 1-3k tokens of prose;
single-hop questions over a tiny corpus. A file per (player, game), modeled on
`knowledgeStore.ts` (caps, Sonnet compaction, chain lock):
`<profileRoot>/gameNotes/<game_key>.md`.

- Written by an automatic END-OF-SESSION pass over the session transcript in
  the backseat stop path. No tool attached, so no speech suppression, and no
  reliance on the model remembering to call it. Mid-session the thread is the
  memory; the file solves cross-session.
- Contents: goals, active quests, plans, notable events, and a taught-ledger
  (concepts already explained, so the tutor never re-explains the scythe).
  NEVER numeric inventory: 602x336 cells cannot read counts reliably and a
  confidently wrong "you have enough cadmium" burns trust permanently.
- Per player, shared across characters (it is a fact about the save, not the
  relationship). Lives outside character dirs; decide interaction with
  factoryReset ("Reset memory" should probably keep it, like knowledge).
- `remember()` unchanged: relationship facts stay per-character.
- Injected whole as its own cached block when a co-op session starts for a
  known `game_key`.

## M4. Pointing

- `point` tool: `{x, y, label?}` normalized to the current frame, attached on
  user ticks alongside search (same suppression rule, same cache lineage).
- Transparent click-through always-on-top window (`setIgnoreMouseEvents`,
  screen-saver level) spanning the shared display; renders a ring plus short
  label at the mapped coordinates, fades after ~4 s. This is a NEW window and
  is not the deleted capture overlay; it renders output only.
- v1 scope: whole-screen shares only (display bounds are known; window-share
  coordinate mapping is deferred). Windows exclusive-fullscreen will hide the
  overlay; borderless-windowed only, documented.
- Why pointing and not control: delivers most of the teaching value of taking
  the mouse with none of the anti-cheat, Accessibility-permission, or trust
  risk (see 260804 discussion; D2 ships BattlEye).

## Cross-cutting

- Any new turn source must check `sharingFor` first (260804: two Suis). The
  search continuation turn and the end-of-session pass both count.
- Cache layout: tools -> brief block -> contract -> notes block -> history.
  Brief and notes are per-session-stable, so they sit before the moving parts
  with breakpoints; read back `cacheRead` per the existing logging.
- Analytics: coop_session_start/end, brief_hit/miss/generated, searches per
  session, points per session.
- App copy and brief prose follow the writing style rule: plain, factual, no
  em-dashes (they are spoken lines and TTS has no sound for a dash).
- Release chores when it ships: website version.json, RELEASE-NOTES, beta
  checklist per the release memory.
