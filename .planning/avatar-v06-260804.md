# Avatar v0.6 (260804) — design and implementation plan

The "Call overlay" grows into an **Avatar** system: the always-on-top window
becomes the character's presence on the desktop (static portrait now, Live2D
optional), controlled by a three-level setting and configured per character
from a new profile tab.

## What ships

1. **Setting rename + levels.** `call_overlay_enabled: boolean` is replaced by
   `avatar_mode: 'off' | 'activity' | 'always'` (default `off`).
   - `off`: never shown.
   - `activity`: shown while any character has a live surface: voice call
     (live/connecting), chess, Draw!, backseat share, or a Minecraft summon
     (online/connecting). Same definition as `activeGameFor` + call membership.
   - `always`: shown whenever the app is open. Characters with activity are
     shown; with none, the currently open chat character; with none of those,
     nothing (an empty roster shows nothing rather than picking arbitrarily).
   - Migration (one-shot, migration.ts): `call_overlay_enabled === true` and no
     `avatar_mode` present writes `avatar_mode: 'activity'`. The old key stays
     in the schema as deprecated so old configs still parse.
2. **Overlay rework** (`callOverlay.ts` + `CallOverlay.tsx` renamed avatar*):
   - **AI only.** The player tile is gone (`CallOverlayPusher` stops appending
     it; the `_user` portrait fetch goes away).
   - **Interactive on hover.** Window runs `setIgnoreMouseEvents(true,
     {forward: true})` so it stays click-through but the renderer still sees
     pointer movement; hovering a tile flips ignore off (IPC), leaving flips it
     back on. Linux does not support `forward` — there the window stays fully
     click-through and hover chrome never appears (documented degrade).
   - **Hover chrome**: a thin glowing outline (periwinkle, matches the
     `.speaking` ring vocabulary) around the overlay while hovered, plus a
     small bottom-right button that appears on hover; the button is
     `-webkit-app-region: drag` (window becomes `movable: true`), so holding
     it drags the window. Position persists.
   - **Resize from corners**: four corner handles visible while hovered.
     Pointer-capture drag in the overlay renderer streams desired bounds to
     main (`setBounds`), scaling the tile size; opposite corner stays
     anchored. Size persists. Bounds live in `UserConfig.avatar_overlay`
     (`{size, x, y}`, written by main on drag/resize end, not
     renderer-settable).
   - **Screen-share self-exclusion**: `win.setContentProtection(true)` — the
     overlay never appears in captures, including Sei's own backseat share.
   - `backgroundThrottling: false` on the overlay webPreferences (Live2D must
     animate while a fullscreen game occludes it).
3. **Per-character avatar prefs** in `UserConfig.avatar_prefs:
   Record<characterId, {frame?: 'circle', always_bright?: boolean}>` — sparse,
   `call_backdrop` precedent; works for foreign characters and never touches
   cloud-synced `character.metadata`.
   - `frame`: tile shape. Circle is the only value today; the enum exists so
     more shapes slot in.
   - `always_bright`: disables the talking indicator entirely — no idle
     dim/scale-down, no speaking ring; the tile is always lit.
4. **Character profile "Avatar" tab** (CharacterPage, third tab after
   Description / Game) with two sub-tabs:
   - **Static**: frame picker (circle only) + "Always bright" toggle.
   - **Live2D (beta)**: upload box accepting a model zip. On import the model
     is extracted, validated and normalized into
     `<profileRoot>/avatars/<characterId>/` (manifest + files); the pane then
     renders a live preview (idle animation running) with Replace / Remove.
5. **Live2D runtime** shared by preview pane and overlay tile:
   - Rendering: `pixi.js@7` + `pixi-live2d-display-lipsyncpatch` (cubism4
     bundle). Cubism 5 Core (`live2dcubismcore.min.js`) is downloaded at build
     time by `scripts/fetch-live2d-core.mjs` from Live2D's official SDK zip
     into `src/renderer/public/live2d/` (gitignored), hooked on
     predev/predist — the mac-audio-tap pattern. The proprietary license
     explicitly permits redistribution inside the app; the repo stays clean of
     the blob. All pixi/plugin code is dynamically imported so the main bundle
     does not grow.
   - Loading: renderer asks main for the model bundle over IPC
     (`avatar:model-files`), builds in-memory `File` objects with relative
     paths, `Live2DModel.from(files)`. No new privileged protocol, no
     file:// fights, arbitrary user model names (GBK etc.) never become URLs.
   - Idle: the SDK's built-in `CubismBreath` (sine head-sway/breath with
     incommensurate cycles) + `CubismEyeBlink` run automatically on a
     motionless model. On top: eye saccades (random focus target every
     0.5-4.5 s, eyes lead via ParamEyeBallX/Y lerp, head follows through the
     focus controller). AIRI-inspired approach, own constants, no copied code.
   - Lip sync: the main window (where TTS actually plays) taps the audio with
     an AnalyserNode, computes an RMS envelope (fast attack ~50 ms, decay
     ~180 ms), and relays `{characterId, level}` at ~25 Hz to the overlay via
     main while that character is audible. The Live2D tile writes
     ParamMouthOpenY directly every frame (this model's LipSync group is
     empty, so group-driven APIs would no-op). If levels stop arriving while
     `speaking` is still true (older path, backpressure), a pseudo-envelope
     keeps the mouth moving rather than freezing open.
   - Expressions: at import, `*.exp3.json` files are registered into the
     normalized model3.json and mapped to a closed emotion set
     (`happy, sad, shy, angry, love, excited, surprised`) by bilingual
     filename keywords (泪/tear→sad, 害羞/shy→shy, 生气/angry→angry,
     爱心/heart→love, 星/star→excited, ...). At speech time the main window
     classifies the spoken line (`onAudible` already carries the text) with a
     small bilingual lexicon and ships the emotion in the overlay state; the
     tile applies the mapped expression and decays to neutral after ~10 s.
     Deliberately NOT LLM-driven in v1: tags in the say/voice path would touch
     every surface's prompt contract. The classifier sits behind one function
     (`classifyEmotion`) so an LLM-tag upgrade replaces the call site, not the
     plumbing.

## Model facts (the test asset)

`_雪熊企划_雪熊少女.zip` (Snow Bear Girl): Cubism 5 export — `.moc3`,
2×4096 textures, physics3, cdi3, 10 `.exp3.json`, VTube Studio sidecars, GBK
filenames. `model3.json` declares EyeBlink but an EMPTY LipSync group and does
NOT reference the expression files — both handled by import normalization.
Standard params all present (ParamMouthOpenY/Form, ParamEyeL/ROpen,
ParamBreath, ParamAngleX/Y/Z, ParamEyeBallX/Y). Emotion expressions: 6 泪
(sad), 7 害羞 (shy), 8 生气 (angry), 9 爱心眼 (love), 10 星星眼 (excited);
1-5 are accessory toggles (hat/phone/mic/gamepad/coat) — importable, visible in
the manifest, unused by auto-emotion.

## Storage & IPC

- `paths.avatarsDir(characterId)` → `<profileRoot>/avatars/<id>/` (outside
  memoryDir, knowledge precedent). Contents: `manifest.json`
  (`{version, name, entry, importedAt, bytes, expressions: [{file, name}],
  emotions: Record<emotion, name>}`) + the extracted model tree.
- Import (main, `src/main/avatar/avatarStore.ts`): zip bytes over IPC (cap
  128 MB), extracted with `jszip` (`decodeFileName`: UTF-8 flag honored, else
  GBK-with-fallback), entries sanitized (reject `..`/absolute, skip
  `__MACOSX`, `._*`), locate the `*.model3.json` with a `FileReferences.Moc`
  (ignore `items_pinned_to_model.json` and other JSON), verify referenced
  files exist, then write a normalized model3.json (inject `Expressions`,
  ensure EyeBlink group) + manifest. Character delete / remove-from-library /
  profile import must clean/carry `avatars/` the same way they handle
  `knowledge/`.
- IPC (all in `src/shared/ipc.ts`): `avatar:import` (id + zip bytes →
  manifest), `avatar:get` (id → manifest|null), `avatar:remove` (id),
  `avatar:model-files` (id → [{path, bytes}]), plus overlay channels:
  existing `voice:overlay-set/state/get` payload extended (participants gain
  `frame`, `alwaysBright`, `live2d`, `emotion`), new `avatar:overlay-level`
  (renderer→main→overlay, throttled), `avatar:overlay-interact`
  (ignore-mouse toggle), `avatar:overlay-bounds` (resize/drag persistence).
- `RENDERER_SETTABLE_KEYS` gains `avatar_mode` and `avatar_prefs`.

## What is deliberately not in v1

- Only `circle` frame; the picker exists to grow.
- No Live2D in call scenes / chat surfaces — overlay + profile preview only.
- Emotion classification is lexicon-based; LLM tags are a documented upgrade.
- Accessory-toggle expressions imported but not surfaced in UI.
- Linux: no hover interactivity (no `forward` support), overlay stays
  display-only there.
